# AstraHealth

Offline-first health monitoring and self-assessment for astronauts on ISS, Moon and Mars missions.
NASA Space Apps Challenge 2026, challenge: *Create Health Monitoring Software for Astronauts on Space Missions*.

> **SI disclosure:** AstraHealth was built with Super Intelligence (SI / AI) assistance. SI-generated images carry a visible **"SI-generated"** watermark in the app, and AI-written text is labelled. Full declaration: [Use of Super Intelligence (SI)](#use-of-super-intelligence-si) below.

Decision support, not diagnosis. All health data in the app is simulated.

## Run locally

```bash
npm install
npm run dev
```

`npm run dev` starts both parts: the **Python server** on port 8787 (body-scan generator and AI proxy, standard library only) and the **web app**. Open the address Vite prints. The app always opens on the login page; a login lasts for the browser tab.

Demo logins: `iss_crew` / `2222`, `moon_crew` / `3333`, `mars_crew` / `1111`, admin `admin` / `0000`.

- **AI key (optional):** copy `server/.env.example` to `server/.env` and set `GEMINI_API_KEY=...`. The key stays in the Python server and never reaches the browser; `server/.env` is git-ignored.
- **Without the key or without Python**, everything still works: the scan uses a built-in browser generator, and the briefing, photo check and SOS checks use offline rules. The UI says which one was used.
- Other commands: `npm run server` (Python server only), `npm run dev:web` (web app only).
- **Health database:** readings, scans, briefings, photos, uploads and SOS events are stored in the browser's IndexedDB. Each astronaut's first login writes 21 days of simulated history; every new reading is appended. To reset, clear the site data.

## 3D organ models (Body Map)

The Body Map shows `image-brain.glb`, `image-heart.glb`, `image-liver.glb`, `image-dna.glb` and `image-leg.glb`. They are built by `src/components/medic/assets/organs/image-to-3d.py` from the five reference images in `assets/organs/source/`:
1. Each organ is cut out of its background.
2. The outline is inflated into a rounded volume (a Poisson solve).
3. Fine relief is added from the image detail.
4. The image becomes the texture.

The DNA is a true 3D double helix with the reference image's proportions and colours. The front view matches each image; the sides and back are a rounded estimate, not a scan. These are illustrations, not clinically validated anatomy.

To regenerate them, install numpy, scipy and pillow, then run:

```bash
python src/components/medic/assets/organs/image-to-3d.py
```

The models are CC0-1.0 (see `assets/organs/LICENSE.txt`). Three.js is MIT licensed, Lucide icons are ISC licensed, and the bundled DM Sans font licence is in `src/components/medic/assets/FONT-LICENSE.txt`.

## Data and privacy

- **Simulations only:** readings, cabin telemetry, clinical assessments and ground communication are demo simulations. SOS messages to the AstraHealth ground lab and the ISS are simulated; no real emergency message is sent.
- **When the AI is enabled**, briefing data and skin photos are sent to Google's Gemini API through the local Python server.
- **Stored on the device:** accounts use demo-grade local storage. Photo Check stores the photo and its assessment in the device's health database, and files attached in "Something wrong?" are kept too. Everything is listed in More → My records, with a "Download my data" export.
- **Journal:** the journal never leaves the device.
- **Mars clock:** it is approximate; ISS and Moon use UTC.
